    실제로 돌려 본 기록

    고객사 안에 있는 AI 모델 서버는 서버마다 지원하는 기능이 다릅니다. 기능이 다른 가짜 서버 5개와 응답 없는 서버 1개에 같은 일을 시켜 본 실제 결과입니다(make compat). 가짜 서버는 정해진 규칙으로만 답합니다. 그래서 답변 품질은 보지 않고, 없는 기능을 알아내서 다른 방법을 쓰는지만 봅니다.

    DB 구조를 바꾸는 파일이 규칙을 지키는지 검사합니다. 실제 릴리스를 만들 때도 같은 검사가 먼저 돌고, 어기면 설치 파일을 만들지 않습니다. 이 검사기는 실제 코드(release.Lint)입니다.

    고른 릴리스의 실제 manifest.json입니다. 설치 파일을 만들 때 생기는 목차이고, 파일별 지문(SHA-256)이 들어 있습니다. 전자서명은 이 파일 내용에 합니다.

    
    
    
  
    
  
    
    어려운 말 풀이
    
    
      
    번들
    설치에 필요한 파일(프로그램 이미지, DB 변경 파일, 목차)을 한 묶음으로 만든 것입니다. 이동식 저장장치로 옮겨 설치합니다.
    
      
    매니페스트
    번들의 목차입니다. 버전, 올릴 수 있는 최소 버전(min_from), DB 구조 변경의 종류, 파일마다의 지문(SHA-256)이 적혀 있습니다.
    
      
    서명
    목차에 찍는 전자 도장입니다. 도장이 맞지 않으면 만든 쪽이 아닌 누군가 바꾼 파일입니다.
    
      
    체크섬
    파일 내용에서 계산한 지문입니다. 파일이 한 바이트만 바뀌어도 달라집니다.
    
      
    스키마 변경
    DB 표의 구조(컬럼·테이블)를 바꾸는 일입니다. none = 바꾸지 않음, compatible = 이전 버전도 쓸 수 있게 바꿈, breaking = 이전 버전이 못 쓸 수 있게 바꿈.
    
      
    expand → contract
    구조 변경을 "먼저 추가만"(expand) 하고, 앱이 옛 구조를 더 쓰지 않게 된 다음 릴리스에서 "정리"(contract) 하는 방식입니다. 그 사이에는 이전 버전도 동작합니다.
    
      
    상태 점검 (health)
    새 버전이 실제로 요청에 응답하는지 확인하는 것입니다.
    
      
    자동 복귀 (롤백)
    앱을 이전 버전으로 되돌리는 것입니다. 데이터를 되돌리는 것이 아닙니다.
    
      
    백업 복구 (restore)
    업그레이드 직전에 만든 사본으로 DB와 첨부 파일을 되돌리는 것입니다.
    
      
    격리 네트워크
    바깥으로 나가는 길이 없는 네트워크입니다. 실제 실행 기록은 이 안에서 만들었습니다.
    
      
    실패 주입
    일부러 고장을 내서 도구가 어떻게 하는지 보는 것입니다. 이 화면에서는 "일부러 고장 내 보기"입니다.
