harborline/upgrade-simulator

브라우저 시뮬레이션 — 판정 로직만 실제 코드(Go → WebAssembly). 서버·도커·네트워크 호출 없음.

인터넷이 없는 고객사 서버에 새 버전을 올릴 때, 잘못되면 어떻게 되돌리는지 보여 주는 데모입니다.

일부러 고장을 내 보면서, 업그레이드 도구가 "계속할지 · 되돌릴지 · 멈출지"를 어떻게 정하는지 확인합니다.

결과

단계 진행

    근거

    고객사 내부 OpenAI 호환 엔드포인트를 흉내 낸 모의 서버 5종 + 응답 없는 엔드포인트에 같은 시나리오를 돌린 실제 실행 결과입니다(make compat). 모의 서버는 규칙 기반이라 모델 품질이 아니라 기능 탐지와 대체 경로만 검증합니다.

    expand → contract 규약 검사기(release.Lint)를 이 브라우저에서 그대로 실행합니다. 릴리스 빌드에서는 같은 검사가 번들 생성을 막습니다.

    선택한 릴리스의 실제 manifest.json(번들 빌드가 만든 파일, SHA-256 포함)입니다. 서명은 이 파일의 원문 바이트에 대해 합니다.

    
    
    
  
    
  
    
    어려운 말 풀이
    
    
      
    번들
    설치에 필요한 파일(프로그램 이미지, DB 변경 파일, 목차)을 한 묶음으로 만든 것입니다. 이동식 저장장치 등으로 옮겨 설치합니다.
    
      
    매니페스트
    번들의 목차입니다. 버전, 올릴 수 있는 최소 버전(min_from), DB 구조 변경의 종류, 파일마다의 지문(SHA-256)이 적혀 있습니다.
    
      
    서명
    목차에 찍는 전자 도장입니다. 도장이 맞지 않으면 만든 쪽이 아닌 누군가 바꾼 파일입니다.
    
      
    체크섬
    파일 내용에서 계산한 지문입니다. 파일이 한 바이트만 바뀌어도 달라집니다.
    
      
    스키마 변경
    DB 표의 구조(컬럼·테이블)를 바꾸는 일입니다. none = 바꾸지 않음, compatible = 이전 버전도 쓸 수 있게 바꿈, breaking = 이전 버전이 못 쓸 수 있게 바꿈.
    
      
    expand → contract
    구조 변경을 "먼저 추가만"(expand) 하고, 앱이 옛 구조를 더 쓰지 않게 된 다음 릴리스에서 "정리"(contract) 하는 방식입니다. 그 사이에는 이전 버전도 동작합니다.
    
      
    상태 점검 (health)
    새 버전이 실제로 요청에 응답하는지 확인하는 것입니다.
    
      
    자동 복귀 (롤백)
    앱을 이전 버전으로 되돌리는 것입니다. 데이터를 되돌리는 것이 아닙니다.
    
      
    백업 복구 (restore)
    업그레이드 직전에 만든 사본으로 DB와 첨부 파일을 되돌리는 것입니다.
    
      
    격리 네트워크
    바깥으로 나가는 길이 없는 네트워크입니다. 실제 실행 기록은 이 안에서 만들었습니다.
    
      
    실패 주입
    일부러 고장을 내서 도구가 어떻게 판단하는지 보는 것입니다.
